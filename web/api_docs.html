PILSEOCORE 本地搜索引擎 API 文档

版本 v0.1.0 · 所有接口返回 JSON(UTF-8)· 支持 CORS

权限控制

服务区分两种角色:

角色认证权限
普通用户无需认证搜索、联想、状态、站点地图、文档、Web UI(只读)
管理员账号密码登录 Web UI,或管理员签发的 API token全部 + 触发穷举遍历、配置后缀/DNS、重建索引、签发/撤销 token

登录(账号密码)

POST /api/auth/login
{"username":"admin","password":"你的密码"}

响应: {"status":"ok","token":"<会话token>","expires_in":43200}

会话 token 12 小时有效,用于 Web UI 管理请求(Authorization: Bearer <会话token>)。

签发 API / MCP Token

管理员登录后签发 token(如 GitHub personal access token),给 API 客户端与 MCP 使用:

POST /api/auth/login                    # 先登录拿会话 token
POST /api/admin/tokens                  # 签发(需会话 token 或已有签发 token)
{"name":"mcp-server"}                   # 用途名称

响应: {"status":"ok","token":"<完整token,仅此一次显示>","name":"mcp-server"}

GET    /api/admin/tokens                # 已签发 token 列表
DELETE /api/admin/tokens/<id>          # 撤销

调用管理 API 时:Authorization: Bearer <签发token>。MCP 启动:pilseocore mcp --token <签发token>(或环境变量 PILSEO_TOKEN),token 无效则拒绝启动。

在 config/engine.conf 配置 admin_user/admin_pass;留空则管理功能整体禁用(管理接口返回 403)。

管理员接口

方法路径说明
GET/api/admin/status扫描状态 + 当前后缀/DNS 配置概要
GET/api/admin/scan-status穷举扫描状态(运行中/完成统计)
POST/api/admin/scan触发穷举遍历
GET/api/admin/config读取 tld.list / dns.list 全文
POST/api/admin/config/tld保存域名后缀列表(空格分隔)
POST/api/admin/config/dns保存 DNS 列表(每行一个)
POST/api/admin/rebuild重建索引(扫描 out/sites)
GET/api/admin/tokens已签发 token 列表
POST/api/admin/tokens签发新 token(供 API/MCP)
DELETE/api/admin/tokens/<id>撤销 token

触发穷举 POST /api/admin/scan

请求体

{
  "max_len": 2,       // 穷举到的最大位数(必填,1-6)
  "min_len": 1,       // 起始位数(可选,默认 1)
  "workers": 64       // 并发数(可选,1-512)
}

响应(202)

{"status":"scan_started","max_len":2}

扫描在后台运行,完成后自动重建索引;通过 /api/admin/scan-status 轮询进度。

基础信息

服务地址: http://127.0.0.1:8896(固定端口,在 config/engine.conf 的 server_port 配置)

接口总览

方法路径说明
GET/Web 搜索界面(Google 风格)
GET/api/search搜索(支持模糊匹配)
GET/api/suggest搜索联想
GET/api/status引擎状态
GET/api/stats索引统计与站点列表
GET/api/sitemap站点地图
GET/api/rebuild重建索引
GET/api/docs本文档

搜索 GET /api/search

参数

参数必填说明
q是搜索关键词(支持中文分词、编辑距离 ≤ 2 模糊匹配)
limit否返回条数,默认 10,最大 100
ai否1 或 true 时附加 AI 摘要(需配置 AI 接入)

响应示例

{
  "query": "智能家居",
  "time_ms": 12,
  "total": 3,
  "ai_summary": "...(可选)",
  "results": [
    {
      "title": "智能家居 - abc.com",
      "url": "https://abc.com/",
      "domain": "abc.com",
      "description": "智能家居 相关资讯...",
      "score": 9.0
    }
  ]
}

联想 GET /api/suggest

参数

参数必填说明
q是输入前缀
limit否返回条数,默认 10,最大 50

响应示例

{
  "query": "智",
  "suggestions": ["智能家居", "人工智能", "智能制造"]
}

状态 GET /api/status

{
  "status": "ok",

  "blocks": 37,
  "loaded_blocks": 3,

索引统计 GET /api/stats

返回全部被索引站点(域名/标题/URL)。

站点地图 GET /api/sitemap?domain=abc.com

返回该域名的 sitemap URL 列表(索引器自动生成 out/sites/<域名>/sitemap.xml)。

重建索引 GET /api/rebuild

重新扫描 out/sites/ 提取标题/描述/关键词并重建倒排索引。

AI 接入

在 config/engine.conf 配置:

ai_enabled = true
ai_endpoint = http://127.0.0.1:11434/v1/chat/completions
ai_model = qwen3:8b
# ai_api_key = 你的key(本地服务留空)

搜索时加 &ai=1 即返回 AI 摘要(OpenAI 兼容,支持 Ollama/llama-server/vLLM 等)。

MCP 支持

启动 MCP Server(stdio):

pilseocore mcp

工具列表: search / suggest / status / sitemap / rebuild

命令行

pilseocore serve [--port 8896]   # 启动搜索服务(自动加载/重建索引)
pilseocore index                 # 手动重建索引
pilseocore search "关键词"        # CLI 搜索
pilseocore mcp                   # MCP Server(stdio)

热点缓存与分块查找

热点缓存: 最近查询结果按 LRU 缓存(hot_cache_size 条,默认 1000,TTL 60 秒),相同查询直接命中。

分块查找: 倒排索引按词首字符分 36+1 块(0-9 a-z other)持久化,查询只路由并加载相关块,避免全量扫描。
